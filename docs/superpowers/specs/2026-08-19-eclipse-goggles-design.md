# Goggles Design

Date: 2026-08-19
Status: Approved design awaiting implementation planning

## Summary

Goggles is a Chrome Manifest V3 extension that makes viewing meaningful visual media an intentional choice. It universally frosts page images and supported videos without attempting to classify whether they were generated by AI. A user reveals one media item at a time.

The product promise is: **visual media requires consent**.

Working identity:

- Name: Goggles
- Tagline: They actually do something.

## Goals

1. Prevent images and videos from capturing attention before the user chooses to view them.
2. Preserve enough page structure that websites remain readable and usable.
3. Present available text descriptions before visual content.
4. Reveal only the selected media item by default.
5. Provide fast, understandable site-level controls.
6. Keep all decisions and page data on the user's device.
7. Support dynamic pages, lazy-loaded media, and common embedded video players.

## Non-goals

- Detecting AI-generated media.
- Judging whether media is harmful, deceptive, or appropriate.
- Blocking network requests for ordinary images in the first release.
- Rewriting household HTTPS traffic at the router.
- Supporting Firefox, Safari, or mobile browsers in the first release.
- Protecting arbitrary WebGL, canvas, or closed-shadow-DOM visuals in the first release.
- Building the separate immediate-scratchpad product discussed during discovery.

## Product behavior

### Meaningful visual media

The extension protects:

- `img`, `picture`, and image-type input elements that exceed the decorative-media thresholds.
- CSS background images on content-sized elements.
- Native `video` elements, including their poster frames.
- YouTube and Vimeo video-player iframes.

The extension leaves these visible and interactive:

- Favicons and browser chrome.
- Images smaller than 48 by 48 CSS pixels unless page semantics identify them as content.
- Buttons, form controls, badges, avatars smaller than the threshold, and navigation icons.
- SVG and canvas elements in the first release.
- Elements with an empty alt attribute that are smaller than 96 by 96 CSS pixels and therefore likely decorative.

CSS background images are protected only when their host element has no visible text or interactive descendants. This prevents a hero background from making its foreground heading or controls unusable.

The classifier must favor page usability when uncertain. Unrecognized iframes and ambiguous visual elements remain unchanged.

### Frost treatment

Protected media keeps its original dimensions and position. The extension places a non-destructive overlay over it with:

- `backdrop-filter: blur(25px)`
- A light-gray layer at 10% opacity
- No saturation adjustment
- No hue, brightness, or contrast adjustment
- No image scaling
- No texture or decorative pattern

Qualifying media always receives the 25px blur. Media too small to accommodate that treatment is classified as decorative and left unchanged.

### Caption dock

An inset caption dock sits along the bottom of protected media. It uses an opaque-enough neutral background to meet WCAG AA contrast for its text and includes:

- The source alt text when it is non-empty and useful.
- Otherwise, the accessible name, nearby figure caption, video title, iframe title, or poster description, in that order.
- Otherwise, the fallback `Image protected by Goggles` or `Video protected by Goggles`.
- A small `Reveal` action on the right.

The whole protected media surface is clickable and keyboard-activatable. The explicit action exists to make the behavior discoverable.

The dock may wrap to multiple lines. On media too small to contain a readable dock, a compact `Reveal image` or `Reveal video` control is shown and the full description is available to assistive technology.

### Image reveal lifecycle

Activating a protected image:

1. Removes the frost and caption dock from that image only.
2. Keeps the image visible for the remainder of the current document session in Protected mode.
3. Provides a small, keyboard-accessible `Protect again` control on focus or hover.
4. Does not reveal other images in the same gallery, page, or site.

Page navigation or reload clears document-session reveals. Revealed media identifiers are not written to persistent storage.

### Video behavior

Native videos are muted and paused as soon as the extension observes them. A protected video uses the same frost and caption dock as an image.

Activating a protected video:

1. Reveals that video only.
2. Does not start playback.
3. Leaves the video muted if the extension muted it.
4. Returns control to the site's native player interface, where playback and unmuting are separate user actions.

For YouTube, Vimeo, and other recognized video iframes, the extension runs its media protection logic in matching child frames where Chrome permissions allow it. The top document also covers the iframe element so pointer input cannot reach the player before reveal.

If a recognized cross-origin player cannot be paused reliably, Goggles temporarily withholds its source before load and restores it on reveal. This strict fallback is limited to recognized video providers to avoid breaking maps, forms, authentication, and other non-video iframes.

### Dynamic content

A document-start content script installs protection as early as Chrome permits. It performs an initial scan and uses a `MutationObserver` to process:

- Newly inserted media.
- Lazy-loaded source and poster changes.
- Elements that become content-sized after layout.
- Infinite-scroll feeds.
- Client-side route transitions that replace page content.

Processing is batched to animation frames and deduplicated. The scanner must not repeatedly rebuild overlays for already classified elements.

## Site modes

The extension popup exposes one mutually exclusive mode per site origin:

### Trusted

- Media appears normally.
- No protection is installed after the mode takes effect.
- Existing overlays are removed immediately.

### Protected

- Default for every site.
- Images and supported videos are frosted.
- Individual reveals last for the current document session.
- A future `Reveal all on this page` command may be added, but it is not part of the first release.

### Strict

- Images and supported videos are frosted.
- Individual reveals remain possible.
- A revealed item is automatically protected again after it has been completely outside the viewport for two continuous seconds.
- Reveals are never persisted.
- Bulk reveal controls are never offered.
- Newly inserted media is always protected even if adjacent media was revealed.

Strict is the permanent blacklist policy. Unlike Protected mode, it does not keep previously viewed media revealed after the user scrolls away.

The popup must support one-click switching among the three modes and show the current site's hostname. Mode changes apply to the active page without requiring a reload.

## Architecture

### Manifest and permissions

The first release uses Chrome Manifest V3 with:

- Static content scripts running at `document_start`.
- `all_frames: true` for supported frames.
- Host access for HTTP and HTTPS pages.
- `storage` permission for preferences.
- The minimum additional permissions proven necessary during implementation.

The extension does not request browsing history, downloads, cookies, or network interception permissions.

### Components

#### Media classifier

Accepts a DOM element and layout information and returns one of:

- `protect-image`
- `protect-video`
- `ignore-decorative`
- `ignore-unsupported`

It contains element-type, size, semantic, and iframe-provider rules. It does not mutate the page.

#### Description resolver

Accepts a classified media element and returns a display description plus its source type. It sanitizes text and never interprets page-provided HTML.

#### Protection renderer

Creates, positions, updates, and removes frost overlays and caption docks. It owns keyboard behavior, focus states, reveal state, and `Protect again` behavior. It does not decide which elements qualify.

#### Video controller

Pauses and mutes native video, coordinates supported child-frame players, and applies the recognized-provider source-withholding fallback. It never initiates playback.

#### Document observer

Runs initial discovery, batches DOM mutations, detects relevant attribute and layout changes, and sends candidates to the classifier.

#### Site-policy store

Reads and writes origin-level Trusted, Protected, or Strict policy through `chrome.storage`. It broadcasts changes to every extension frame in the active tab.

#### Extension popup

Displays the current hostname and three site modes. It contains no page content and does not display browsing history.

### Data flow

1. The content script requests the current origin policy.
2. Trusted mode exits after removing any existing protection.
3. Protected or Strict mode starts the document observer.
4. Candidates pass through the classifier and description resolver.
5. The renderer protects qualifying images; the renderer and video controller protect qualifying videos.
6. A reveal event updates in-memory document state only.
7. A popup policy change is stored by origin and broadcast to the active tab for immediate reconciliation.

## Accessibility

- Every protected item is keyboard reachable without changing the page's original tab order more than necessary.
- Enter and Space reveal the focused media.
- Focus indicators remain visible against light and dark pages.
- Caption text and controls meet WCAG AA contrast.
- The accessible label includes the resolved description and reveal action.
- Original alt attributes are never overwritten.
- Decorative images do not gain noisy announcements.
- Reduced-motion preferences are respected; frost removal uses no required animation.
- A revealed video does not autoplay or unmute.

## Privacy and security

- All classification, description resolution, and policy decisions run locally.
- The extension sends no page text, URLs, images, or usage events to a server.
- Descriptions are inserted as text, never page-provided HTML.
- Page styles and scripts must not be able to trigger a reveal by dispatching ordinary synthetic clicks.
- Extension state uses unguessable internal identifiers rather than page-provided IDs.
- The extension avoids running logic in Chrome internal pages and other schemes where content scripts are prohibited.

## Failure handling

- If classification fails, leave the element unchanged and log a local development diagnostic; never remove page content.
- If overlay positioning becomes stale, update it on the next batched layout observation.
- If a native video cannot be paused, keep it muted and protected.
- If a recognized iframe cannot be controlled, use the source-withholding fallback.
- If storage is unavailable, use Protected mode for the current document without persisting changes.
- If an overlay conflicts with a site's stacking context, render it in an isolated extension-owned shadow root attached to a stable top-level layer.

## Testing strategy

### Unit tests

- Meaningful-versus-decorative classification boundaries.
- Description precedence and sanitization.
- Origin policy serialization and defaults.
- Reveal state transitions for images and videos.
- Recognized iframe-provider matching.

### DOM integration tests

- Images, pictures, CSS backgrounds, and changing sources.
- Long, missing, empty, and malicious alt text.
- Caption wrapping and compact controls.
- Native video pause, mute, reveal, and no-autoplay behavior.
- Mutation batching, lazy loading, and infinite-scroll insertion.
- Trusted, Protected, and Strict changes without reload.
- Strict-mode automatic re-protection after media leaves the viewport.
- Keyboard and focus behavior.

### Browser tests

- Conventional articles and image galleries.
- Social and infinite-scroll feeds.
- YouTube and Vimeo embeds.
- Nested and dynamically created frames.
- Responsive layout, zoom, and device-pixel-ratio changes.
- Fullscreen attempts before and after reveal.
- Back/forward navigation and client-side route transitions.

### Acceptance criteria

1. On a supported article page, meaningful images are frosted before they can command attention during normal loading.
2. Each protected image retains its page dimensions and shows a readable bottom caption.
3. Revealing one item never reveals a sibling.
4. Protected video never starts or unmutes as a side effect of reveal.
5. Trusted mode removes protection immediately; Protected and Strict install it immediately.
6. Lazy-loaded media is protected without noticeable page slowdown.
7. No page content or browsing information leaves the device.
8. Core flows work with mouse, keyboard, and a screen reader.

## Household deployment

The first release is a user-installed Chrome extension. A later household edition may provide instructions or managed-browser policy files that force-install and configure the extension on devices the household administrator controls.

Router-level HTML rewriting is rejected because HTTPS prevents a normal router from modifying page structure. A decrypting proxy would require trusted certificates on every device, expose household traffic, and break applications. DNS filtering may complement Goggles by blocking known media hosts, but it cannot provide the per-image frost-and-reveal experience.

## Delivery boundaries

The first implementation plan covers one Chrome extension, local preferences, image protection, native video protection, recognized YouTube and Vimeo embeds, the caption-dock UI, and automated tests. Managed household deployment, additional browsers, remote reporting, AI detection, canvas/WebGL protection, and the immediate-scratchpad business idea require separate future designs.
